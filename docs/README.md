# docs/ — เอกสารและหน้านำเสนอ

โฟลเดอร์นี้เก็บ **ของที่เอาไปให้คนอ่านได้เลย** เปิดจากดิสก์ ไม่ต้องมีเซิร์ฟเวอร์ ไม่ต้องต่อเน็ต

| ไฟล์ | คืออะไร | เปิดยังไง |
|---|---|---|
| `presentation.html` | **หน้านำเสนอลูกค้า** · 14 กลุ่มงาน 83 ฟังก์ชัน 8 ตัวอย่างกดเล่นได้ 14 ภาพหน้าจอจริง · 2.1 MB ไฟล์เดียวจบ | ดับเบิลคลิก แล้วเลื่อนลงพรีเซนต์ |
| `handoff.html` | **เอกสารส่งต่องาน** ฉบับอ่านสบาย มีสารบัญลอยข้าง สั่งพิมพ์ได้ | ดับเบิลคลิก |
| `demo-standalone.html` | **เดโมทั้งแอปในไฟล์เดียว** สำหรับเอาไปนำเสนอ · ไม่ต้องมีเซิร์ฟเวอร์ ไม่ต้องต่อเน็ต | `node tools/bundle-demo.mjs --wrap` แล้วดับเบิลคลิก |
| `build/` | ชิ้นส่วนและสคริปต์ที่ประกอบสองไฟล์ข้างบน | ดูข้างล่าง |
| `ledger-posting-rules.md` | **เอกสารที่ส่งให้ทีม Ledger Bridge** ก่อนนัดคุยกฎลงบัญชี | ส่งไฟล์นี้ไปเลย |

> **สองไฟล์ `.html` ข้างบนเป็นผลลัพธ์ ห้ามแก้ตรง ๆ** — แก้ที่ต้นทางแล้วประกอบใหม่
> ไม่งั้นการแก้จะหายทั้งหมดในการประกอบครั้งถัดไป

## แก้หน้านำเสนอลูกค้า

ต้นทางอยู่ใน `build/` ทั้งหมด

```
build/
├─ deck.template.html   โครงหลัก · CSS ทั้งชุด · หัวข้อ 01–10
├─ parts/
│  ├─ play.css  play.js         ตัวอย่างกดเล่นได้ 5 อันแรก
│  ├─ finance.css  finance.js   ตัวอย่างฝั่งบัญชี (ใบสำคัญ · งบกำไรขาดทุน)
│  ├─ wifi.css  wifi.js         ตัวอย่างหัวข้อ 14 (คำถามจากเจ้าหน้าที่ตาม ม.26)
│  ├─ astra.css                 **ชั้นดีไซน์ทั้งหน้า** — token สองธีม โครงหน้า แผงทุกชนิด
│  ├─ astra.js                  แถบวัด · ตัวนับหัวข้อ · ปุ่มลัด · เผยตัวเมื่อเลื่อนถึง · สลับธีม
│  ├─ atelier.css               ชั้น modern Thai hospitality — ภาพปก โทนอุ่น และจังหวะ editorial
│  ├─ sec-11-12.html            หัวข้อ 11–12
│  ├─ sec-finance.html          หัวข้อบัญชี (แทรกเป็น 05)
│  ├─ sec-wifi.html             หัวข้อ 14
│  └─ demo-*.html               โครง HTML ของตัวอย่างแต่ละอัน
├─ shots/              ภาพหน้าจอจริง 17 รูป (ฝังเป็น data URI ตอนประกอบ)
├─ assemble.py         รอบ 1
├─ assemble2.py        รอบ 2 — ยกบัญชีขึ้นเป็นหัวข้อ 05 แล้วเลื่อนที่เหลือ
├─ assemble3.py        รอบ 3 — เพิ่มหัวข้อ 14 Wi-Fi + ซ่อมแถบนำทาง
├─ assemble4.py        รอบ 4 — ทับชั้นดีไซน์ ASTRA
├─ assemble5.py        รอบ 5 — ปรับภาษาและภาพให้เป็นงานขายแบบ hospitality
├─ build.py            ตัวสั่งรันทั้งสี่รอบแล้วก๊อปผลไปเป็น ../presentation.html
├─ md2html.py          แปลง ../../HANDOFF.md → ../handoff.html
└─ check-deck.mjs      ตรวจหน้าที่ประกอบเสร็จด้วย Chrome จริง
```

```bash
cd docs/build && python build.py          # → docs/presentation.html
```

**ตรวจด้วยเบราว์เซอร์จริงต่อทุกครั้ง** (ต้องมี Chrome ในเครื่อง):

```bash
npm i --no-save puppeteer-core          # จากรากของ repo
cd docs/build && node check-deck.mjs
```

> **`--no-save` และรันจากรากสำคัญ** — `npm i` ที่รันใน `docs/build` จะเดินขึ้นไปเจอ
> `package.json` ของแอปที่ราก แล้วเติม `puppeteer-core` เป็น dependency ของแอปจริง
> ทั้งที่มันเป็นเครื่องมือของเอกสารเท่านั้น (พลาดมาแล้วครั้งหนึ่ง)

`check-deck.mjs` ตรวจให้สี่อย่าง: ลิงก์นำทางทั้ง 14 อันเลขตรงปลายทางและปลายทางมีจริง ·
ตัวอย่างกดเล่นได้ทำงาน · ไม่มี error ในหน้า · มือถือไม่เลื่อนข้าง

### สามอย่างที่ต้องเช็กเองทุกครั้งที่เพิ่มหัวข้อ
1. **เลข `<span class="n">` ตรงกับ `id="gNN"`** ของหัวข้อนั้น
2. **ลิงก์นำทางเลขตรงกับปลายทาง** — เคยพลาดแล้ว กด "05" ไปโผล่หัวข้อ 06 อยู่หลายวัน
   สาเหตุคือ `re.sub` หาไม่เจอแล้วคืนข้อความเดิมเฉย ๆ ไม่ error
3. **ตัวเลขที่โฆษณาหัวหน้าเพจตรงกับที่นับได้จริง** — ผลรวม `tally` ต้องเท่าจำนวน `<li>`
   `assemble3.py` ตรวจสามข้อนี้ให้แล้วตอนจบ ถ้าเพิ่มรอบใหม่ให้ตรวจต่อในแนวเดียวกัน

### ชั้นดีไซน์ ASTRA (รอบ 4)

หน้าตาทั้งหมดมาจาก `parts/astra.css` — **ทับของเดิม ไม่รื้อ markup**
เพราะตัวอย่างกดเล่นได้ 8 อันผูกกับชื่อคลาสและ id เดิม รื้อแล้วมันพังแบบที่
หน้ายังดูปกติตอนโหลด แต่กดปุ่มไม่มีอะไรเกิดขึ้น — อาการที่จะไปโผล่ตอนยืนหน้าลูกค้า

กลไกที่ทำให้ทับได้ทั้งหน้าโดยไม่ต้องตามแก้ทีละจุด: CSS เดิมใช้ `--paper`
(สว่างสุด) กับ `--ink` (มืดสุด) เป็นคู่ตรงข้ามอย่างสม่ำเสมอ **สลับสองตัวนี้**
แล้วทุกการจับคู่จึงยังอ่านออก เหลือแค่แผงที่ใช้ `--ink` เป็นพื้นหลัง
กับสีที่ฝังเป็นเลขฐานสิบหก 14 จุด ที่ต้องสั่งใหม่ให้ชัด

**สองธีม** — กลางคืนเป็นค่าตั้งต้น กดปุ่มบนแถบหรือกด `D` สลับเป็นกลางวัน
จำค่าไว้ใน localStorage ของเครื่องคนนำเสนอ · ของเดิมตั้งใจล็อกธีมสว่างเพราะ
หน้านี้ถูกฉายขึ้นจอต่อหน้าลูกค้า **เหตุผลนั้นยังจริง** จึงไม่ตัดทิ้ง
ห้องไหนสว่างจัดจนจอมืดอ่านไม่ออก กดกลับได้ในคลิกเดียว

**ปุ่มลัดสำหรับคนนำเสนอ** — `↑` `↓` `←` `→` `PgUp` `PgDn` `Space` ข้ามหัวข้อ ·
`Home` `End` หัว–ท้าย · `D` สลับธีม (ไม่ทำงานตอนโฟกัสอยู่ในช่องกรอก)

**สองอย่างที่ต้องระวังถ้าจะแก้ astra.js**
1. คลาส `.rv` (เผยตัวเมื่อเลื่อนถึง) ใส่ด้วย JS ไม่ใช่เขียนใน HTML —
   ถ้าเขียนใน HTML แล้ว JS พังหรือถูกบล็อก ลูกค้าจะเห็นหน้าว่างเปล่า
2. ตัวนับหัวข้อเกาะ `aria-current` ผ่าน MutationObserver **ห้ามอ่านตอน scroll** —
   handler ของ scroll วิ่งก่อน IntersectionObserver อัปเดต ตัวนับจะช้ากว่า
   แถบนำทางหนึ่งจังหวะตลอด แล้วคนดูเห็นเลขสองตัวขัดกันบนจอ (เจอมาแล้ว)

### ทำไมประกอบสามรอบแรก
แต่ละรอบเกิดคนละวันตามที่ลูกค้าขอเพิ่ม และรอบหลังต้อง **เลื่อนเลขหัวข้อ** ของรอบก่อน
(แทรกหัวข้อบัญชีเป็น 05 ทำให้ 05–12 เดิมกลายเป็น 06–13) การเลื่อนบนไฟล์ที่ประกอบแล้ว
ปลอดภัยกว่าไปแก้เลขในเทมเพลตทุกจุดแล้วเสี่ยงลืมจุดใดจุดหนึ่ง

## ใบเสนอราคา

```bash
node tools/make-quote.mjs                                  # ดีล 43 ห้อง (ค่าเริ่มต้น)
node tools/make-quote.mjs --rooms 28 --to "โรงแรมบ้านสวน"   # ลูกค้ารายอื่น
```

ได้ `docs/quote.html` — เปิดแล้วสั่งพิมพ์ได้เลย แยกเป็นสองแผ่น A4 อัตโนมัติ

แผ่นแรกเป็นการ์ดสามใบให้ลูกค้าเลือก · แผ่นสองเป็นใบเสนอราคาทางการ
มีเลขที่ วันที่ เงื่อนไขชำระเงิน และช่องเซ็น สำหรับเอาเข้าประชุมขออนุมัติงบ

**ห้ามแก้ตัวเลขในไฟล์ HTML โดยตรง** · กติกาการคิดราคาอยู่ที่
`tools/quote-price.mjs` ที่เดียว และมีเทสคุมทุกข้อ (`tests/quote.test.cjs`)
ราคาเดียวกันโผล่สามที่ในเอกสาร — แก้มือแล้วจะมีสักที่ที่ลืม
แล้วลูกค้าจะเป็นคนเจอก่อนเรา

เกิน 60 ห้องสคริปต์จะปฏิเสธ ไม่เดาราคาให้ เพราะงานจริงอยู่ที่การรวมรายงาน
ข้ามสาขาและย้ายข้อมูลจากระบบเดิม ซึ่งตีเป็นสูตรไม่ได้ · ที่มาของกติกาทั้งหมด
อยู่ใน `docs/packages.md`
