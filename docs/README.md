# docs/ — เอกสารและหน้านำเสนอ

โฟลเดอร์นี้เก็บ **ของที่เอาไปให้คนอ่านได้เลย** เปิดจากดิสก์ ไม่ต้องมีเซิร์ฟเวอร์ ไม่ต้องต่อเน็ต

| ไฟล์ | คืออะไร | เปิดยังไง |
|---|---|---|
| `presentation.html` | **หน้านำเสนอลูกค้า** · 14 กลุ่มงาน 83 ฟังก์ชัน 8 ตัวอย่างกดเล่นได้ 14 ภาพหน้าจอจริง · 2.1 MB ไฟล์เดียวจบ | ดับเบิลคลิก แล้วเลื่อนลงพรีเซนต์ |
| `handoff.html` | **เอกสารส่งต่องาน** ฉบับอ่านสบาย มีสารบัญลอยข้าง สั่งพิมพ์ได้ | ดับเบิลคลิก |
| `build/` | ชิ้นส่วนและสคริปต์ที่ประกอบสองไฟล์ข้างบน | ดูข้างล่าง |

> **สองไฟล์ `.html` ข้างบนเป็นผลลัพธ์ ห้ามแก้ตรง ๆ** — แก้ที่ต้นทางแล้วประกอบใหม่
> ไม่งั้นการแก้จะหายทั้งหมดในการประกอบครั้งถัดไป

## แก้หน้านำเสนอลูกค้า

ต้นทางอยู่ใน `build/` ทั้งหมด

```
build/
├─ deck.template.html   โครงหลัก · CSS ทั้งชุด · หัวข้อ 01–10
├─ parts/
│  ├─ play.css  play.js         ตัวอย่างกดเล่นได้ 5 อันแรก
│  ├─ finance.css  finance.js   ตัวอย่างฝั่งบัญชี (ใบสำคัญ · งบกำไรขาดทุน)
│  ├─ wifi.css  wifi.js         ตัวอย่างหัวข้อ 14 (คำถามจากเจ้าหน้าที่ตาม ม.26)
│  ├─ sec-11-12.html            หัวข้อ 11–12
│  ├─ sec-finance.html          หัวข้อบัญชี (แทรกเป็น 05)
│  ├─ sec-wifi.html             หัวข้อ 14
│  └─ demo-*.html               โครง HTML ของตัวอย่างแต่ละอัน
├─ shots/              ภาพหน้าจอจริง 17 รูป (ฝังเป็น data URI ตอนประกอบ)
├─ assemble.py         รอบ 1
├─ assemble2.py        รอบ 2 — ยกบัญชีขึ้นเป็นหัวข้อ 05 แล้วเลื่อนที่เหลือ
├─ assemble3.py        รอบ 3 — เพิ่มหัวข้อ 14 Wi-Fi + ซ่อมแถบนำทาง
├─ build.py            ตัวสั่งรันทั้งสามรอบแล้วก๊อปผลไปเป็น ../presentation.html
├─ md2html.py          แปลง ../../HANDOFF.md → ../handoff.html
└─ check-deck.mjs      ตรวจหน้าที่ประกอบเสร็จด้วย Chrome จริง
```

```bash
cd docs/build && python build.py          # → docs/presentation.html
```

**ตรวจด้วยเบราว์เซอร์จริงต่อทุกครั้ง** (ต้องมี Chrome ในเครื่อง):

```bash
cd docs/build && npm i puppeteer-core && node check-deck.mjs
```

`check-deck.mjs` ตรวจให้สี่อย่าง: ลิงก์นำทางทั้ง 14 อันเลขตรงปลายทางและปลายทางมีจริง ·
ตัวอย่างกดเล่นได้ทำงาน · ไม่มี error ในหน้า · มือถือไม่เลื่อนข้าง

### สามอย่างที่ต้องเช็กเองทุกครั้งที่เพิ่มหัวข้อ
1. **เลข `<span class="n">` ตรงกับ `id="gNN"`** ของหัวข้อนั้น
2. **ลิงก์นำทางเลขตรงกับปลายทาง** — เคยพลาดแล้ว กด "05" ไปโผล่หัวข้อ 06 อยู่หลายวัน
   สาเหตุคือ `re.sub` หาไม่เจอแล้วคืนข้อความเดิมเฉย ๆ ไม่ error
3. **ตัวเลขที่โฆษณาหัวหน้าเพจตรงกับที่นับได้จริง** — ผลรวม `tally` ต้องเท่าจำนวน `<li>`
   `assemble3.py` ตรวจสามข้อนี้ให้แล้วตอนจบ ถ้าเพิ่มรอบใหม่ให้ตรวจต่อในแนวเดียวกัน

### ทำไมประกอบสามรอบ
แต่ละรอบเกิดคนละวันตามที่ลูกค้าขอเพิ่ม และรอบหลังต้อง **เลื่อนเลขหัวข้อ** ของรอบก่อน
(แทรกหัวข้อบัญชีเป็น 05 ทำให้ 05–12 เดิมกลายเป็น 06–13) การเลื่อนบนไฟล์ที่ประกอบแล้ว
ปลอดภัยกว่าไปแก้เลขในเทมเพลตทุกจุดแล้วเสี่ยงลืมจุดใดจุดหนึ่ง

## แก้เอกสารส่งต่องาน

แก้ `HANDOFF.md` ในรากของ repo แล้ว

```bash
pip install markdown                      # ครั้งเดียว
cd docs/build && python md2html.py        # → docs/handoff.html
```

สารบัญสร้างจากหัวข้อ `##` อัตโนมัติ ไม่ต้องไปเพิ่มมือ
