0 · สรุปสามบรรทัด

Sentiara คือ PMS (Property Management System) สำหรับโรงแรมและคอนโดปล่อยเช่ารายวันในประเทศไทย จุดขายไม่ใช่ความสวย แต่คือ ทำตามกฎหมายไทยได้จริง — ภาษี ทะเบียนผู้พัก การแจ้งคนต่างด้าว และ log Wi-Fi สถานะ: หลังบ้านใช้งานได้จริงและมีเทสคุม 186 ข้อ · หน้าจอครบ 5 มุมมอง · ยังไม่ได้ต่อ OTA และระบบราชการจริง

2 · ทำอะไรได้บ้าง

2.1 งานหน้าบ้าน — จองถึงเช็กเอาต์

  • ค้นห้องว่างตามช่วงวัน · จองตรง (ไม่ผ่าน OTA) · จองแบบ walk-in ที่เคาน์เตอร์
  • กันจองซ้ำด้วยฐานข้อมูล ไม่ใช่ด้วยโค้ด — ตาราง room_night มี UNIQUE(room_id, night) สองคนกดพร้อมกันคนที่สองได้ IntegrityError ไม่ใช่ห้องซ้ำ
  • จัดห้องติดกันให้ครอบครัว (src/lib/allocate.ts)
  • เรตวันหยุด (ศุกร์–เสาร์) แยกจากเรตวันธรรมดา · เรต OTA แยกจากเรตขายตรง
  • เช็กอิน เช็กเอาต์ ย้ายห้อง ต่อคืน ยกเลิก

2.2 บิลและการเงินหน้าบ้าน

  • บิลเดียวต่อการเข้าพัก (folio) · ค่าห้องรายคืน อาหาร มินิบาร์ ซักรีด เข้าบิลอัตโนมัติ
  • รับชำระหลายวิธี · มัดจำ · ยอดค้าง
  • ใบกำกับภาษีเต็มรูป ม.86/4 — ครบทุกรายการที่กฎหมายบังคับ รวมจำนวนเงินเป็นตัวอักษร
  • ใบลดหนี้ ม.86/10 — อ้างใบกำกับเดิมบังคับ · เกินยอดคงเหลือไม่ได้ · ใช้ VAT อัตราของใบเดิม
  • เลขที่เอกสารเป็น พ.ศ. (INV-2569-00001 · CN-2569-00001) เรียงไม่ข้ามเลข
  • VAT ถอดออกจากราคา ไม่ใช่บวกเพิ่ม — ราคาที่แขกเห็นคือราคาที่จ่าย

2.3 บัญชี — ต่อกับ Ledger Bridge (โปรแกรมบัญชีคู่)

  • ปิดยอดรายคืน (night audit) รับรู้รายได้ค่าห้องตามคืนที่พักจริง
  • ส่ง เหตุการณ์ เข้าโปรแกรมบัญชี ไม่ส่งใบสำคัญ (ดูข้อ 4)
  • คิว outbox ส่งซ้ำได้ไม่ซ้ำยอด · ดูสถานะทุกรายการได้
  • รายจ่าย 11 หมวดที่ตรงกับผังบัญชีจริง · ภาษีหัก ณ ที่จ่าย ตาม ท.ป.4/2528
  • งบกำไรขาดทุนย่อและกระแสเงินสดในจอเจ้าของ

2.4 งานที่กฎหมายบังคับ (จุดขายที่คู่แข่งไม่มี)

2.5 งานแม่บ้านและสถานะห้อง

  • ใบงานสถานะ open → doing → inspect → done (+ inspect → doing ตีกลับ)
  • ต้องมีรูป 3 รูปก่อนส่งตรวจ · ตีกลับต้องมีเหตุผลและรูปถูกล้าง
  • ห้องกลับไปขายได้ตอนหัวหน้าอนุมัติ ไม่ใช่ตอนแม่บ้านกดเสร็จ — คนตรวจงานตัวเองคือมาตรฐานที่หายไป
  • ห้องที่มีแขกมาถึงวันนี้ได้ priority 1 อัตโนมัติ

2.6 Wi-Fi ที่พัก (งานล่าสุด)

  • ออกรหัสอัตโนมัติตอนเช็กอิน ชื่อผู้ใช้เป็นเลขห้อง รหัสสุ่มรายห้อง
  • หมดอายุเองหลังเช็กเอาต์ + ผ่อนผัน 3 ชั่วโมง
  • จำกัดจำนวนเครื่องต่อห้อง (ค่าเริ่ม 3)
  • บันทึกทุก session: MAC · IP · จุดกระจายสัญญาณ · เวลา · ปริมาณข้อมูล ผูกกับการจอง
  • รายงานตัวตนตาม ม.26 คืนผู้พักทุกคนที่ลงทะเบียนในห้องนั้น
  • ระบบ ปฏิเสธ ถ้าตั้งเวลาเก็บต่ำกว่า 90 วัน
  • ต่อกับอุปกรณ์ยี่ห้อไหนก็ได้ผ่าน RADIUS / captive portal
  • PMS เป็นชั้น "ใคร" · อุปกรณ์เครือข่ายยังเป็นชั้น "ทำอะไร" — ไม่แย่งงานกัน โดยตั้งใจ

2.7 ผู้ใช้ สิทธิ์ ร่องรอย

  • ล็อกอินด้วย บัตร + PIN (เหมาะกับเคาน์เตอร์ ไม่ใช่อีเมล+รหัสผ่าน)
  • 14 สิทธิ์ · 6 บทบาท: owner manager (ทั้งหมด) · front · hk · tech · pos
  • ทุกเส้นทาง API มียาม ไม่มีเส้นทางไหนเปิดโล่ง
  • ร่องรอยตรวจสอบเก็บ ชื่อพนักงานซ้ำไว้ในแถว ไม่ใช่แค่ id — คนลาออกแล้วเปลี่ยนชื่อ ร่องรอยเก่าต้องยังอ่านออก
  • /audit เขียนอย่างเดียว ไม่มีเส้นทางลบหรือแก้

2.8 สำรองข้อมูลและติดตั้ง

  • สำรองแบบ ออนไลน์ ด้วย sqlite3.Connection.backup() ไม่ใช่ก๊อปไฟล์ (ปลอดภัยกับ WAL)
  • ตรวจสำเนา (integrity_check + นับแถวทุกตารางหลัก) ก่อนถือว่าใช้ได้
  • กู้คืนเก็บไฟล์เดิมไว้เป็น .before-restore-<stamp>.db เสมอ
  • เริ่มระบบ.bat สำรองอัตโนมัติก่อนเปิดทุกครั้ง เก็บ 30 ชุดล่าสุด
  • แพ็กเป็นโปรแกรม.py แพ็กเป็น .exe ไฟล์เดียว ลูกค้าดับเบิลคลิกเปิด ไม่ต้องลง Python

2.9 ของที่อยู่ในเดโมแต่ยังไม่มีหลังบ้าน

แชท · ใบแจ้งซ่อม · ระบบสะสมแต้ม · ตั้งค่าโรงแรม · ChivaGo · กลอนประตู NFC · พลังงาน · แจ้งเหตุเพลิงไหม้ ทั้งหมดนี้ ทำงานเต็มรูปในโหมดเดโม (เก็บใน localStorage) แต่ในโหมด live ยังไม่ต่อหลังบ้าน

4 · การต่อกับ Ledger Bridge — เข้าใจให้ถูกก่อนแตะ

ชุดเชื่อมต่อของผู้ขายอยู่ที่ C:\Users\User\OneDrive\Desktop\Senmodel\ส่งให้-Sentiara (ไม่ขึ้น git โดยตั้งใจ — มีกุญแจกับรหัสผ่านข้างใน และหนัก 152MB · ดู .gitignore)

หลักที่ต้องไม่ลืม

  1. Sentiara เป็นฝ่ายส่งเข้ามา ไม่ใช่ฝ่ายถูกดึง
  2. ส่ง "เหตุการณ์" ไม่ส่ง "ใบสำคัญ" — กฎลงบัญชี (posting rules) อยู่ฝั่ง Ledger Bridge เราไม่ตัดสินว่าเดบิต/เครดิตบัญชีอะไร นั่นเป็นเส้นที่เขาขีดไว้
  3. จำนวนเงินส่งเป็นสตริงเสมอ เช่น "1650.00" ไม่ส่งเป็นตัวเลข
  4. ใบสำคัญที่ลงแล้ว ลบไม่ได้ แก้ไม่ได้ ต้องตั้งรายการกลับเท่านั้น
  5. วันที่ใช้เวลาเครื่อง (ไทย) ห้ามใช้ UTC
  6. กุญแจเครื่องจักร (machine key) ใช้ส่งเข้า · ถ้าจะ ดึงตัวเลขมาแสดง ให้ใช้บัญชีผู้ใช้บทบาท viewer อย่าไปขอขยายสิทธิ์ให้กุญแจเครื่องจักร — เส้นที่เขาตั้งใจขีด
  7. ชุดที่มีเป็น ชุดทดสอบ กุญแจกับรหัสในนั้นใช้กับเครื่องลูกค้าจริงไม่ได้

  • eventId ผูกกับ ref ที่สุ่ม ไม่ใช่ id ที่ไล่เลข — เลขไล่ทำให้เดาเอกสารอื่นได้

⚠ กับดักที่ทำให้ข้อมูลหายเงียบ ๆ (สำคัญที่สุดในเอกสารนี้)

ปลายทางมี watermark — seq ที่ต่ำกว่าค่านั้นจะถูกรายงานว่าเป็น duplicates ผลคือได้ HTTP 202 พร้อม sent: 4 เหมือนสำเร็จทุกอย่าง แต่ไม่มีอะไรเข้าคิวเลย

แก้ไว้แล้วสองชั้น: - align_sequence() ดันเลขให้พ้น watermark ก่อนส่ง - send_pending() นับ inserted จากคำตอบจริง ไม่เชื่อรหัส HTTP

ต้นตอ: สคริปต์ตรวจของผู้ขายเองใช้ Date.now() เป็น seq ทำให้ watermark ถูกดันไปไกล บทเรียน: อย่าเชื่อ 2xx เชื่อตัวเลขที่ปลายทางบอกว่ารับไปเท่าไร

ยังไม่ได้ทำ

กฎลงบัญชีฝั่ง Ledger Bridge ยังไม่ได้ตั้ง — ต้องคุยกับทีมเขาว่าแต่ละเหตุการณ์ลงบัญชีอะไร ที่อยู่ endpoint ในโค้ดยังเป็นค่าสมมุติ (ดูคอมเมนต์)

7.7 ภาษาไทยในที่ที่ต้องเป็น ASCII

  • b"ข้อความไทย" → SyntaxError (bytes literal รับ ASCII เท่านั้น)
  • ภาษาไทยใน HTTP header → UnicodeEncodeError (พลาดสองครั้ง — ชื่อ header x-wifi-secret และค่า token) บทเรียน: header กับ bytes literal เป็น ASCII เสมอ

7.8 เลขบัตรประชาชนมั่วในเทส — แล้ว validator จับได้

ใส่ 1101700207250 ในเทส แต่ validator ที่เพิ่งเขียนปฏิเสธ เพราะหลักตรวจสอบไม่ตรง คำนวณจากสูตรจริงได้ 1101700207251 การที่เทสพังคือหลักฐานว่า validator ทำงาน — สูตร: (11 - Σ d[i]×(13-i) mod 11) mod 10

7.9 การ patch แบบไม่มี assert ล้มเงียบ

แก้ tuple PERMISSIONS ด้วยการแทนสตริง แต่ช่องว่างไม่ตรง → ไม่มีอะไรเปลี่ยน ไม่มี error โผล่ตอนรันเป็น ValueError: ไม่รู้จักสิทธิ์ 'housekeeping' บทเรียน: ทุกสคริปต์ที่แทนข้อความต้อง assert ว่าเจอกี่ครั้ง — ใช้ทั่วโปรเจกต์แล้ว (def sub(...))

7.10 แถบนำทางหน้านำเสนอเพี้ยนเพราะ re.sub ไม่ error

สคริปต์ประกอบเดคหา regex ที่ยังไม่เกิด re.sub คืนข้อความเดิมเฉย ๆ ผลคือแถบนำทางมีลิงก์ 12 อันจาก 13 หัวข้อ กด "05" ไปโผล่หัวข้อ 06 และไม่มีใครรู้ แก้: สร้างแถบใหม่ทั้งแถบ + ใช้ re.subn เช็กจำนวนที่แทนได้ + ตรวจซ้ำว่าลิงก์ตรงปลายทาง บทเรียน: re.sub ที่ไม่เช็กผลลัพธ์คือการแก้ที่อาจไม่เกิดขึ้น

7.11 เครื่องมือที่ใช้ไม่ได้บน Windows

  • pkill -f "uvicorn pms.app" ไม่ทำงาน → ใช้ PowerShell Get-NetTCPConnection หาพอร์ตแล้ว Stop-Process
  • heredoc ของ bash แปลง \n เป็นบรรทัดจริง ทำ Python string literal พัง → ใช้เครื่องมือแก้ไฟล์ หรือ chr(10)

  • /tmp ใน Bash tool ไม่ใช่ path ที่ Python เห็น → ใช้โฟลเดอร์ scratchpad

7.15 การรวมงานสองสายที่ทับกัน (10 ก.ย. 2569)

ห้าม force-push ในสถานการณ์นี้ — จะทับงาน ~3,600 บรรทัดของอีกฝั่ง ท่าที่ใช้: push งานตัวเองขึ้น branch สำรองก่อน → ลอง merge บน branch ทิ้ง → แก้ conflict → เทสผ่าน → ff main บทเรียน: "merge ผ่าน" ไม่เท่ากับ "รวมถูก" — สองฟีเจอร์ชื่อไม่ชนกันรวมผ่านได้ทั้งที่ทับกัน
